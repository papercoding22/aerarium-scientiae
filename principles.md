# Knowledge Base Principles

## Keep It Simple

Prefer simple folders, clear filenames, and lightweight templates. Avoid complex systems until there is a real need.

## Organize By Domain

Main knowledge should live under domains such as `ai`, `software-engineering`, `business`, and `cross-domain`.

## Write Atomic Concept Notes

One concept note should explain one idea. If a note starts collecting many separate ideas, split it.

## Separate Source, Concept, And Application

- Source notes record what a source said.
- Concept notes record reusable understanding.
- Application notes record how to use an idea in life, work, or business.

## Preserve Uncertainty

Do not make weak claims sound certain. Use confidence levels and mark open questions clearly.

## Prefer Source-Backed Knowledge

Important claims should point to a source when practical. This is not a strict academic citation system, but provenance should be visible.

## Connect Ideas Only When Useful

Use normal Markdown links. Add `Related Notes` only when the connection helps future understanding or retrieval.

## Make Notes Useful For Learning

Use summaries, simple explanations, examples, and visual representations when possible.

## Review Weekly

The weekly review keeps the system clean without requiring daily maintenance.
